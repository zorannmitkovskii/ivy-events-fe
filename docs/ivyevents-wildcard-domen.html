Адреси име.ivyevents.mk: сертификати и домен

Упатство чекор по чекор за да работат адресите на настаните (ana-marko.ivyevents.mk), добавувачите и агенциите. Треба ви пристап до серверот каде работи nginx и до панелот каде се управува DNS-от на ivyevents.mk. Чекорите означени со Claude се во кодот и ги правам јас.

Напредок

0 од 0 чекори готови · се чува само во овој прелистувач

1

Проверете ги постоечките сертификати вие

Во nginx.conf се користат два сертификати, во различни папки:

ПапкаЈа користи
/etc/letsencrypt/live/ivyevents.mk/ivyevents.mk, www., auth.
/etc/letsencrypt/live/ivyevents.mk-0001/api.ivyevents.mk

-0001 значи дека certbot направил втор сертификат со исто име, најчесто затоа што подоцна е додаден домен. Двата мора да бидат важечки.

а) На серверот: сите сертификати, домени и рок

sudo certbot certificates
# Името на сервисот/контејнерот го наоѓате со: docker ps
docker compose run --rm certbot certificates
# или, без compose:
docker run --rm -v /etc/letsencrypt:/etc/letsencrypt certbot/certbot certificates

За секој сертификат гледајте:

  • Domains: кои имиња ги покрива. Засега *.ivyevents.mk не треба да го има.
  • Expiry Date: колку дена важи. Под 30 дена значи дека обновувањето не работи (чекор 2).

б) Од кој било компјутер: што навистина служи серверот

Во Git Bash (на Windows) или терминал:

for h in ivyevents.mk www.ivyevents.mk api.ivyevents.mk auth.ivyevents.mk; do
  echo "== $h"
  echo | openssl s_client -connect $h:443 -servername $h 2>/dev/null \
    | openssl x509 -noout -subject -issuer -enddate -ext subjectAltName
done

notAfter е рокот на важење, а Subject Alternative Name ги покажува имињата што ги покрива сертификатот.

Во PowerShell, без openssl, само рокот:

$req = [Net.HttpWebRequest]::Create("https://ivyevents.mk"); $req.GetResponse().Dispose()
$req.ServicePoint.Certificate | Format-List Subject, Issuer, GetExpirationDateString
2

Проверете го автоматското обновување вие

# Проба на обновување, без вистински промени
sudo certbot renew --dry-run

# Дали има тајмер/cron што го извршува
systemctl list-timers | grep -i certbot
sudo crontab -l | grep -i certbot

Ако certbot е во Docker, обновувањето најчесто е cron на хостот што го стартува контејнерот. Проверете го и тој cron.

По обновување nginx мора да се reload-ира, инаку продолжува да го служи стариот сертификат од меморија. Проверете дали во /etc/letsencrypt/renewal/*.conf или во cron-от има --deploy-hook "nginx -s reload" (за Docker: docker exec <nginx-контејнер> nginx -s reload).

Кај кого е DNS-от вие

Најважното прашање за чекор 6: дали провајдерот има API што certbot може да го користи.

# Git Bash / Linux
dig NS ivyevents.mk +short
dig A ivyevents.mk +short
dig A api.ivyevents.mk +short

# PowerShell
Resolve-DnsName ivyevents.mk -Type NS
Resolve-DnsName ivyevents.mk -Type A
NS покажува конЗначи
*.ns.cloudflare.comCloudflare: plugin certbot-dns-cloudflare, најлесно
*.digitalocean.com, *.awsdns-*, Hetzner, OVH, Gandi…Има certbot plugin (certbot-dns-<провајдер>)
македонски регистрар / хостинг без APIНема автоматика. Решение: DNS-от да се премести на Cloudflare (бесплатно), или рачен DNS-01 на секои ~60 дена (чекор 6б)

Запишете ја IP адресата од dig A ivyevents.mk. Ви треба во чекор 5.

4

CAA записи вие

dig CAA ivyevents.mk +short
  • Празно: во ред, секој издавач смее.
  • Има записи: мора да постои 0 issuewild "letsencrypt.org". Постоечкиот issue ги покрива само обичните сертификати. Без issuewild Let's Encrypt одбива да издаде wildcard.
5

Додајте wildcard DNS запис вие

Во DNS панелот додадете:

ТипИмеВредностTTL
A* (т.е. *.ivyevents.mk)истата IP како ivyevents.mkAuto / 300
AAAA*IPv6 адресата, само ако ivyevents.mk веќе има AAAAAuto / 300

Постоечките api, auth, www, test записи остануваат. Точен запис секогаш има предност пред wildcard.

Cloudflare: ставете го записот на DNS only (сив облак), бидејќи сертификатот е на вашиот сервер. Ако сакате proxied (портокалов облак), SSL режимот мора да биде Full (strict).

Проверка, со име што не постои никаде (по неколку минути):

dig A proba-123.ivyevents.mk +short     # треба да ја врати истата IP
Resolve-DnsName proba-123.ivyevents.mk   # PowerShell
6

Wildcard сертификат (DNS-01) вие

Let's Encrypt издава wildcard само преку DNS-01. Сегашниот начин (/.well-known/acme-challenge/ во nginx) е HTTP-01 и за ова не работи. Wildcard покрива едно ниво: ana-marko.ivyevents.mk да, a.b.ivyevents.mk не, па и самиот ivyevents.mk се додава посебно.

Препорака: нов сертификат со посебно име ivyevents.mk-wildcard. Сегашните два не се допираат, па ништо од постоечкото не може да се скрши.

1. Во Cloudflare: My Profile → API Tokens → Create Token → „Edit zone DNS“, ограничено на зоната ivyevents.mk.

2. На серверот:

sudo apt install -y python3-certbot-dns-cloudflare     # или: pip install certbot-dns-cloudflare

sudo mkdir -p /root/.secrets
sudo sh -c 'echo "dns_cloudflare_api_token = ОВДЕ_ТОКЕНОТ" > /root/.secrets/cloudflare.ini'
sudo chmod 600 /root/.secrets/cloudflare.ini

sudo certbot certonly \
  --dns-cloudflare \
  --dns-cloudflare-credentials /root/.secrets/cloudflare.ini \
  --dns-cloudflare-propagation-seconds 30 \
  --cert-name ivyevents.mk-wildcard \
  -d ivyevents.mk -d '*.ivyevents.mk'

Обновувањето потоа е автоматско, со истиот plugin (проверете повторно со certbot renew --dry-run).

docker run --rm \
  -v /etc/letsencrypt:/etc/letsencrypt \
  -v /root/.secrets:/secrets:ro \
  certbot/dns-cloudflare certonly \
    --dns-cloudflare \
    --dns-cloudflare-credentials /secrets/cloudflare.ini \
    --dns-cloudflare-propagation-seconds 30 \
    --cert-name ivyevents.mk-wildcard \
    -d ivyevents.mk -d '*.ivyevents.mk'

За обновување, во cron-от за renew користете ја истата слика certbot/dns-cloudflare, не certbot/certbot. Обичната слика го нема plugin-от.

sudo certbot certonly --manual --preferred-challenges dns \
  --cert-name ivyevents.mk-wildcard \
  -d ivyevents.mk -d '*.ivyevents.mk'

Certbot ќе побара TXT запис _acme-challenge.ivyevents.mk (можно е два, по еден за секое име; тогаш двата стојат истовремено). Додајте го во DNS панелот и пред да притиснете Enter проверете:

dig TXT _acme-challenge.ivyevents.mk +short
Рачниот сертификат не се обновува сам. На секои ~60 дена ова мора да се повтори, инаку по 90 дена сите поддомени паѓаат со предупредување во прелистувачот. Затоа е подобро DNS-от да оди на провајдер со API.

Проверка дека е издаден:

sudo certbot certificates --cert-name ivyevents.mk-wildcard
# Domains: ivyevents.mk *.ivyevents.mk
# Certificate Path: /etc/letsencrypt/live/ivyevents.mk-wildcard/fullchain.pem
7

Nginx блок за поддомените вие

Во ivy-events-fe/vue-project/nginx.conf (продукцискиот) додадете го ова после постоечките server блокови. Nginx секогаш прво бара точно име (api., auth., www., test.) пред regex, па тие не се засегнати.

# ─── Сајтовите на *.ivyevents.mk: настани, добавувачи, агенции ───
# Истиот SPA. Апликацијата го чита името од hostname-от, па тука нема rewrite.
# Едно ниво, без точка: a.b.ivyevents.mk не одговара на ништо.

server {
    listen 80;
    server_name "~^[a-z0-9][a-z0-9-]{0,62}\.ivyevents\.mk$";
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name "~^(?<site_label>[a-z0-9][a-z0-9-]{0,62})\.ivyevents\.mk$";

    ssl_certificate     /etc/letsencrypt/live/ivyevents.mk-wildcard/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ivyevents.mk-wildcard/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    add_header X-Request-Id $request_id always;

    location = /env.js {
        proxy_pass http://fe_upstream/env.js;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Request-Id $request_id;
        add_header Cache-Control "no-store" always;
        add_header Content-Type "application/javascript; charset=utf-8" always;
    }

    location / {
        proxy_pass http://fe_upstream;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Request-Id $request_id;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port 443;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

Проверка и reload:

# nginx на хостот
sudo nginx -t && sudo systemctl reload nginx

# nginx во Docker (името од: docker ps)
docker exec <nginx-контејнер> nginx -t && docker exec <nginx-контејнер> nginx -s reload
Ако nginx е во Docker, папката /etc/letsencrypt мора да е mount-ната во контејнерот (веќе е, бидејќи сегашните сертификати работат). Новата ivyevents.mk-wildcard папка ќе се појави таму сама.

Кодот Claude

Ова го правам јас, по ваше одобрување. Тука е за да знаете што уште фали:

  • Адреса на API-то од поддомен. Денес baseUrl.js на ana-marko.ivyevents.mk би барал https://ana-marko.ivyevents.mk:8282, што не постои. Треба секој *.ivyevents.mk да оди на https://api.ivyevents.mk. CORS не треба да се менува: јавните endpoints (/v1/api/public/**) веќе примаат барања од секаде.
  • Резервирање адреса за настан (BE):
    • endpoint за организаторот;
    • предлог од името: „Ана & Марко“ → ana-marko;
    • 409 ако е зафатено, со предлог;
    • одбивање на резервирани зборови;
    • вклучи/исклучи.
  • Поле „Адреса на поканата“ во поставките на настанот (FE), и линковите и QR кодовите да ја користат новата адреса.
  • Отворени прашања кон вас: дали е бесплатно или дел од пакет (CUSTOM_DOMAIN / INV_PREMIUM / INV_PRO), и кој смее да ја вклучи.

Крајна проверка вие

# 1. DNS
dig A proba-123.ivyevents.mk +short

# 2. Сертификатот на поддомен ги покрива *.ivyevents.mk
echo | openssl s_client -connect proba-123.ivyevents.mk:443 -servername proba-123.ivyevents.mk 2>/dev/null \
  | openssl x509 -noout -enddate -ext subjectAltName

# 3. Nginx го служи SPA-то (треба 200)
curl -sI https://proba-123.ivyevents.mk | head -1

# 4. Backend-от знае на кого е адресата (404 = слободна, 200 = зафатена и вклучена)
curl -s "https://api.ivyevents.mk/v1/api/public/site?host=studio-lumiere.ivyevents.mk"

# 5. Постоечките адреси сè уште работат
for h in ivyevents.mk api.ivyevents.mk auth.ivyevents.mk; do curl -sI https://$h | head -1; done

Во прелистувач: https://proba-123.ivyevents.mk треба да се отвори без безбедносно предупредување и да ја прикаже насловната страница (адресата е слободна, па нема сајт).
